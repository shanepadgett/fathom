# Technical Planning

For changing requirements, technical decisions, architecture, repository layout,
or build plans. Skip for implementing agreed work or consulting decisions.

- Start from `docs/requirements/`; change requirements only for agreed decisions.
- Follow [the tracker](../technical/tracker.md): technology versions, architecture
  and layout, then build plan. Handle one topic at a time.
- Record accepted decisions in `docs/technical/` and update the tracker. Keep
  proposals distinct; revisit conflicts before implementing them.
- Planning ends only when explicitly completed in the tracker. Keep `AGENTS.md`
  consistent; separate design or prototype work does not end planning.

Read only references needed for the current topic.
