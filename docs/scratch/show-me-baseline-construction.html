Fathom. baseline

How this process is built, and how a message moves.

Start at baseline/main.ts. The host mounts named services. Plugins consume those names. The UI never imports a plugin.

Boot

  1. 1
    main.ts — process only. Reads env, builds the UI with Vite if public/ is missing, opens a desktop window when Deno has BrowserWindow.
  2. 2
    host.ts — new Context() then ctx.plugin(...) in this order. Each await waits until injects exist.
  3. 3
    http.ts — binds 127.0.0.1:4050, serves public/, hands /api/ to routes.ts.

Seams — provide vs inject

A service class calls super(ctx, "name"). That name appears on ctx. Consumers list it in inject. They do not import the provider file.

workspace provide
plugins/workspace.ts
Used by sessions (data dir), fs (path jail), bash/script tools, agent (system prompt).
sessions provide inject workspace
plugins/sessions.ts
SQLite. Titles a chat on first user append. Emits session/changed.
model provide
plugins/model.ts
Lists signed-in models. Streams. Does not know sessions.
tools provide
plugins/tools.ts
Registry only. call checks the schema then runs the tool.
fs provide inject workspace
plugins/fs.ts
Disk I/O. No hashes. Split a backend only when a second one exists.
subprocess provide
plugins/subprocess.ts
Spawn. tool-bash and tool-script inject this.
tool-fs / tool-bash / tool-script consumer Model-facing schemas. Hashline lives in tool-fs, not on disk.
surfaces provide Editor, agent, and chat register. The header only shows who mounted. Leave a plugin out to turn a view off.
agent provide inject sessions, model, tools, workspace
plugins/agent.ts
The loop. Writes messages through sessions. Does not name chats.

One send

ui/app.tsx Composer calls api.send(id, text).
ui/api.ts POST /api/sessions/:id/messages
http.ts Not API. Forwards /api/ to routes.
routes.ts ctx.agent.submit(id, text) then returns a snapshot. Does not wait for the model.
agent.ts sessions.append user message (titles if still “New chat”), status running, then drive.
sessions.ts Writes SQLite. Emits session/changed.
routes.ts SSE GET /api/sessions/:id/live listens and pushes a full snapshot.
ui/api.ts EventSource updates the transcript. Sidebar refreshes from GET /api/sessions.

Inside drive()

model.resolve(provider, id)
default gpt-6-astra, else first available
tools.list() → pi-ai tool specs
model.stream(systemPrompt, messages, tools)
append / replaceLast partials every 80ms
stream.result() → final assistant message
if toolCall → tools.call(name, args, { sessionId, signal })
sessions.append toolResult
repeat up to 32 steps, then idle
