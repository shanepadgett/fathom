Runtime

What Pi agent-core pulls from @earendil-works/pi-ai for the model turn. Source check: packages/agent/src/types.ts, agent-loop.ts, agent.ts, and harness compaction helpers. Import path is the package root unless noted.

Call boundary

Agent-core defines StreamFn against these Pi AI types:

// packages/agent/src/types.ts — satisfied by Models.streamSimple type StreamFn = ( model: Model<Api>, context: Context, options?: SimpleStreamOptions, ) => AssistantMessageEventStream | Promise<AssistantMessageEventStream>;

Failures stay in the stream (error / done events and a final AssistantMessage with stopReason "error" or "aborted"), not thrown from StreamFn.

Types

id, name, api, provider, baseUrl, reasoning, input modalities, cost, contextWindow, maxTokens, optional thinking levels / headers. Wire protocol id string ("anthropic-messages", "openai-responses", "openai-completions", "openai-codex-responses", …). systemPrompt?, messages, tools?. UserMessage | AssistantMessage | ToolResultMessage. role, content blocks, stopReason, usage, errorMessage?, provider metadata. toolCallId, toolName, content, isError, timestamp. name, description, TypeBox parameters. id, name, arguments (on assistant content). Content block shapes on user/assistant/tool messages. input/output/cache tokens and cost fields on assistant turns. stop | length | toolUse | error | aborted | pending. minimal | low | medium | high | xhigh | max; model side adds off. Extends stream options with portable reasoning settings (thinking level, budgets, abort signal, sessionId, cacheRetention, transport, …). Stream protocol: start, text/thinking/toolcall start|delta|end, done, error. Deltas carry partial assistant snapshot. Async iterable of events; result() → final AssistantMessage. Used on agent options when wiring stream calls (token budgets; sse / websocket / auto for Codex-style transports).

Models collection API

Built with createModels({ credentials?, authContext? }). Agent-core does not construct this; the host does. Methods a runtime host needs:

Register and inspect providers. Sync catalog reads. Portable stream — the usual StreamFn binding. Full provider-specific options when simple is not enough. Non-streaming helpers (compaction / one-shot calls in harness code use these via Models). Dynamic model lists (OpenRouter later if needed).

Also: hasApi(model, api), calculateCost, getSupportedThinkingLevels, clampThinkingLevel from the root export.

Functions agent-core calls

Parse/validate tool JSON against the TypeBox schema before execute (agent-loop.ts). Generic push/async-iterable stream; agent loop builds its own event stream on this class. Flatten text blocks to a string (compaction / summarization). Ids for sessions/messages in harness code. Retried model calls in compaction paths. Re-exported TypeBox bits for tool schemas (agent also depends on typebox directly).

TypeBox

Tool parameters are TypeBox schemas. Pi AI re-exports Type, Static, TSchema. Validation is validateToolArguments.

Not required for the loop boundary

Image generation APIs, @earendil-works/pi-ai/compat globals, OAuth modules (host/auth concern), and every provider outside the five we register. Harness session/JSONL types are agent-core, not pi-ai.
