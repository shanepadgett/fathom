Overview

Package: @earendil-works/pi-ai at 0.83.0 (packages/ai in the Pi monorepo).

Pi’s agent package (@earendil-works/pi-agent-core) sits on top of this. The loop does not import providers or OAuth. It takes a StreamFn — same shape as Models.streamSimple — plus Pi AI types for models, context, messages, tools, and stream events. Auth and provider registration live outside the loop, usually in the host that builds the Models collection and passes models.streamSimple.bind(models).

That boundary is the inventory below: what an agent runtime on top of Pi AI actually imports. Two sections: Runtime (models, messages, streaming, tools) and Auth (credentials, login, resolve).

Providers we register

Factories from @earendil-works/pi-ai/providers/*, not builtinModels().

anthropicProvider() — Messages API. API key + Claude Pro/Max OAuth. openaiProvider() — Responses API. API key only (OPENAI_API_KEY). openaiCodexProvider() — ChatGPT Plus/Pro OAuth (Codex backend). Separate id from platform OpenAI. xaiProvider() — Completions/Responses. API key + device-code OAuth. openrouterProvider() — Completions. API key + OAuth that mints a long-lived key.

Collection setup:

import { createModels } from "@earendil-works/pi-ai"; import { anthropicProvider } from "@earendil-works/pi-ai/providers/anthropic"; import { openaiProvider } from "@earendil-works/pi-ai/providers/openai"; import { openaiCodexProvider } from "@earendil-works/pi-ai/providers/openai-codex"; import { xaiProvider } from "@earendil-works/pi-ai/providers/xai"; import { openrouterProvider } from "@earendil-works/pi-ai/providers/openrouter"; const models = createModels({ credentials: store }); for (const p of [ anthropicProvider(), openaiProvider(), openaiCodexProvider(), xaiProvider(), openrouterProvider(), ]) { models.setProvider(p); }
