Session and run

Hosts call one main method. Desktop sends a user message. Web sends a slice of thread messages from an @mention. Optional fields cover tool limits, extra system text, and a client-side run id so a flaky reconnect does not start the same run twice. The return value is a stream of events.

// Host entry (intent, not final API) runtime.run({ sessionId, input: | { kind: "user_message"; text: string; images?: unknown[]; actor?: Actor } | { kind: "thread_slice"; messages: ThreadMessage[]; actor?: Actor }, toolPolicy?: ToolPolicy, systemFragments?: string[], clientRunId?: string, }): AsyncIterable<RuntimeEvent>;

Each prompt follows the same path. Load the session and branch from SQLite. Build the message list and the prompt the model will see. Pick the model, system prompt, tools, credentials, and permissions. Hand that to our loop, start the run, and save records as events arrive. Send safe events out. Save the new branch tip and run status. If the process dies mid-run, clean up on restart.

Only the runtime may change the in-memory messages for the active run. UI and extensions go through runtime commands so the database and memory stay in sync. One run per session at a time. If the session is busy, the host queues or rejects.
