Build the runtime

Build the engine before either host gets far. Hosts can grow against a stable runtime.run and event stream. Do not let desktop UI or web thread mapping invent session rules while the runtime is still unfinished.

Phase 1 — prove the loop

Throwaway Deno spike with the exact Pi AI version. One prompt through our own loop stub calling AI Core. One of our tools. Try tool calls, steer, cancel, and event order. Build the model prompt in our code. Write down every Node compatibility problem with Pi AI.

Done when our loop drives Pi AI in Deno and the behaviors we need (single run, cancel, tool order, stream pieces) are covered by tests.

Phase 2 — settle how sessions are saved

Write concrete examples for a normal run, tool approval, retry, abort, branch, and history trim. Decide whether the main structure is an event log, a graph, or both. Design the smallest SQLite schema that fits those examples. Prove we can recover after a crash mid-stream or mid-tool.

Done when session and branch state rebuild cleanly from SQLite alone.

Phase 3 — headless runtime

Add AgentSession (or whatever we name it). Load agent state from the database. Save loop events through one internal listener. Add prompt building and our own history trim. Add model, credential, tool, permission, and workspace services. Run it all in a replaceable Deno worker. Expose generation-tagged commands and events with no desktop UI yet. Support clean reload and force-kill recovery.

Done when a test can create, run, close, reopen, branch, trim, and continue a session.
