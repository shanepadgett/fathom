UI shell

The desktop app is a coding-agent host: UI on top of Agent Runtime. Layout, panels, the message box, tool views, embedded editors, shortcuts. It talks to the runtime through the host. It does not store the agent’s long-term memory. Panels read runtime state and events.

Prefer simple declared UI contributions when they are enough. Do not make the stable plugin API depend on private UI framework objects.

We support up through Tier 3. Tier 4 — a plugin replaces the whole app — is not something we promise.

Tier What Support?
0 Theme colors and basic tokens Yes
1 Slots: tool views, replace message box, panels, commands Yes (spike starts here)
2 Layout presets, show/hide chrome, required areas (transcript, message box, approval) Yes
3 Embedded editor or browser views Yes, carefully
4 Replace the entire app No

UI plugins may add command palette items, menus, shortcuts, how a message block looks, how a tool call looks, panels, status items, and settings forms. Required areas stay required: transcript, message box, and approval path cannot disappear behind a layout preset.
