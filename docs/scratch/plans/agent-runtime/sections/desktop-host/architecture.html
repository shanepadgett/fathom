Desktop architecture

The backend is in charge. The UI only gets plain data it can copy: commands, events, and snapshots. It does not get live objects from inside the engine.

Tools and extensions

Early commands stay simple: send a prompt, steer, abort, pick a model, set thinking level, approve or reject a tool, trim history, create or open a branch, turn tools on or off, open or close a workspace.

The engine runs in its own Deno worker from the start. That split is about app lifecycle (reload, crash, restart), not sandbox security. Extensions are trusted code we wrote or installed on purpose, and they load inside that same worker. Everything crossing the worker boundary must be plain data. That also makes it easier later to move the engine into another process or machine without rewriting the UI contracts.
