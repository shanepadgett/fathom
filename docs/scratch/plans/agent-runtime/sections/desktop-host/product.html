Desktop Host — product

Desktop is the main place developers work with the agent. It starts as one person chatting against a project folder. File and shell tools run through a local or remote execution environment. The UI is richer than web chat. Extensions can load from the repo or the user’s machine.

Multiplayer can come later without changing runtime basics: still one session, still one active run, messages tagged with who sent them. Desktop multiplayer is mostly UI, host, and sync work — not a second agent engine.

Session mapping is simple in the first UI: one desktop session id maps to one agent session id. The app shows streaming text and blocks, prompt / steer / abort, tool progress and approvals, model and account picking, and session / branch navigation.

Save and recovery failures must be obvious. Restarting the UI must not lose agent state and must not act like the UI owns that state.
