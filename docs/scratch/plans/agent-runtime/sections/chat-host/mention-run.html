Mention run

When someone @mentions the agent, the chat product builds a short slice of messages since the agent last spoke. The host makes sure no other run is already active for that session, then calls runtime.run with kind: "thread_slice". Events stream back, and the chat product posts the agent’s reply into the thread.

Host locks the session and calls runtime.run

Slice rules are a product decision the host owns: which messages count, how far back, whether system notes are included, how attachments become runtime inputs. Runtime should get a clean slice, not a dump of the whole thread database.

Use clientRunId so a flaky reconnect does not start the same run twice. Pass actor when the person who mentioned the agent matters for audit or permissions.
