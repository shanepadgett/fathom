AI Core

Pi AI (@earendil-works/pi-ai) is how we talk to model providers. Each provider has its own request shapes, stream chunks, tool-call formats, stop reasons, and usage fields. Pi AI turns that into one API: pick a model and credentials, send messages, stream text / reasoning / tool calls back as shared types.

That is the problem it solves. Without it we maintain Anthropic, OpenAI, Google, OpenRouter, Bedrock, and the next API ourselves. Provider churn is not where we want to spend time.

What it brings:

Types live in Pi’s packages/ai/src/types.ts, models.ts, auth/types.ts. Pin at 0.83.0 when it becomes a real dependency. First prove Anthropic and OpenAI streams in Deno, including tool calls that arrive in pieces, cancel mid-stream, and usage/stop reasons. OAuth polish and Bedrock can wait.

Credentials: each provider knows its own API key or OAuth flow. On a request, Pi looks up a saved credential or falls back to env vars. Default store is in-memory; auth.json is optional. We should plug in our own store (disk early, OS keychain on desktop later). Secrets do not belong in session rows.

OAuth already in Pi 0.83.0: openai-codex (ChatGPT Plus/Pro; plain openai is key only), anthropic (Claude Pro/Max), xai (device code), openrouter (PKCE → long-lived key). Copilot and others exist too. Desktop can start on Pi’s Codex login; later the app should own browser launch, callback, refresh, account pick, and keychain.
